Verification redesign Plan CI workflow

CI workflow with background steps

The E2E (host) job now has to install Chromium for Playwright. Instead of adding one more step to wait through, the job starts the slow independent setup as background steps and builds in the foreground. It waits for everything only right before the tests run. The owner approved the CI change on 20 Nov ("you can just do it"). It ships in PR #10.

What GitHub Actions gives us

As of 25 June 2026, GitHub Actions can run steps concurrently, and each step keeps its own log (changelog, workflow syntax):

  • background: true: start a step and move straight on to the next one.
  • wait: <id> waits for named background steps; wait-all waits for every one still running. A background step's failure, outputs and env changes surface at that wait.
  • cancel: <id> stops a background step. An implicit wait-all runs before cleanup.
  • parallel: is shorthand for "start these in the background, then wait for all of them". Our CI already uses it.
  • Limits: at most 10 background steps per job, and none declared inside a composite action (running a composite as a background step is fine).

Today

Everything waits for the slowest setup. Adding Chromium as another member of that group doesn't work, because the install needs node_modules (the Playwright CLI) and runs apt for its system libraries.

Proposed

Why this order:

  • Background: system packages and Python start at once and don't block Node.
  • Foreground Node install, no build: the Chromium install needs the Playwright CLI from node_modules, so the install comes first.
  • Wait for system packages before Chromium. playwright install --with-deps calls apt-get. Two apt runs at once fight over the dpkg lock, so Chromium starts only after the apt step ends. This is the one ordering the job can't avoid.
  • Chromium in the background, build in the foreground. The workspace build is the longest local step, and the browser download overlaps with it.
  • wait-all before the tests, so every setup failure surfaces there, with its own log, before any test runs.
  • Cache: the browser goes into PLAYWRIGHT_BROWSERS_PATH under the workspace, cached by Playwright version. A version bump changes the key.

The job

  e2e-host:
    name: E2E (${{ matrix.lane }})
    runs-on: ubuntu-latest
    env:
      PLAYWRIGHT_BROWSERS_PATH: ${{ github.workspace }}/.cache/ms-playwright
    strategy:
      fail-fast: false
      matrix:
        lane:
          - host
    steps:
      - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4
        with:
          persist-credentials: false

      - name: Set up system packages
        id: system-packages
        background: true
        uses: ./.github/actions/setup-system-packages

      - name: Set up Python workspace
        id: python-workspace
        if: matrix.lane == 'host'
        background: true
        uses: ./.github/actions/setup-python-workspace

      - name: Set up Node workspace
        uses: ./.github/actions/setup-agent-vm
        with:
          build: 'false'

      - name: Restore Chromium
        uses: actions/cache@0057852bfaa89a56745cba8c7296529d2fc39830 # v4
        with:
          path: .cache/ms-playwright
          key: ${{ runner.os }}-playwright-1.61.1-chromium-headless-shell

      - wait: system-packages

      - name: Install Chromium for Playwright
        id: chromium
        background: true
        run: pnpm --filter ./packages/sign-in-test-support exec playwright install --with-deps --only-shell chromium

      - name: Build workspace
        run: pnpm build

      - wait-all

      - name: Record browser version
        run: pnpm --filter ./packages/sign-in-test-support exec playwright --version

      - name: Run E2E lane
        env:
          AGENT_VM_E2E_SKIP_WORKSPACE_BUILD: '1'
        run: pnpm run test:e2e:${{ matrix.lane }}

The validation job and the check aggregator don't change. No unit or integration test launches a browser.

CallWhyCost
Headless shell only (--only-shell)The tests are headless. The shell is smaller and is what the spike ran.A future headed test would need the full browser.
Cache key pinned to the Playwright versionThe version decides the browser revision. The spike saw revision 1228 for 1.61.1.The key's version has to be bumped together with the package pin.

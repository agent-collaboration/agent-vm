Each row is a case in a switch on the facts' kind with an inline x satisfies never. Readiness reads enrolment only; a stale confirmation never routes to a setup step. The handler reads facts once per request and renders the chosen page; GET never writes.

Authenticator step and recovery codes

The step page uses Better Auth's two-factor/enable and verify-totp. After a correct code, the island holds the recovery codes from enable's reply in memory only and shows them with a Finish button; navigation away is disabled until Finish, which then GETs /setup. A reload re-decides: the factor is enrolled, so the codes are gone.

M2 · Decline

States pending | accepted | rejected | canceled as Better Auth stores them; our only transition is pending → rejected. Endpoint (in invitation-decline-plugin.ts, beside passkey-confirmation-plugin.ts): require a verified current session whose email equals the invitation's; then one Drizzle update status = 'rejected' WHERE id = ? AND status = 'pending' AND expiresAt > now. One row changed → declined; zero rows → re-read: accepted or rejected → already-answered; expired → expired; not found or not the recipient → not-found (no detail). An intent record is written before and an outcome after, like the other people changes.

Staging

  • Entrypoint. sign-in-host-cloudflare/src/staging/index.ts builds the same configuration with the same core factory and options, plus Better Auth's testUtils plugin. Its own Worker, D1 and auth secret.
  • Routes, each requiring the staging secret (from agent-vault): POST /__staging/test-identity creates or finds a user under the .invalid test domain with verified email and signs it in through testUtils, returning its cookie; POST /__staging/reset deletes test-domain users, their sessions and memberships, organizations owned only by test users, and asks Central to remove those organizations' stores.
  • M4 · test identity: absent → created → signed-in → reset; reset only matches the test domain.
  • Run. A script scripts/verify-auth/staging-journeys.mts resets, creates identities, drives the six journeys in headless Chrome from signed-in identities, and computes TOTP codes from the displayed key and the server's Date header.
  • Production checks in the same script against production: /__staging/* → 404; a staging cookie → refused; artifact search finds no testUtils; configured owner not under the test domain.

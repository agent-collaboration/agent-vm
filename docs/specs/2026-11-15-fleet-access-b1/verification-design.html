SO2: the real sign-in journey

SO2 is lasting. The approved target is real workerd with D1 and locked Better Auth 1.7.11, plus Node with better-sqlite3. B1 uses a central stand-in; it proves neither the central consumer nor an integrated central flow. Better Auth’s own time-dependent expiries run under controlled system time on Node. Workerd claims nothing that depends on that uncontrolled library clock. Heavy suites go to Sunclaw, as the source directs.

The people observation must use the real organization plugin and its native permission checks, exact verified-email acceptance, the original public route allowlist, owner protection, intent/outcome writes and an unconfirmed intent when completion cannot be proved. It must show that client input cannot set fleetState, and only a server Provisioned result makes it ready. Complete SO2 source.

The factor observation uses the actual cookie jar and the actual current session. It must distinguish first-app session rotation from later same-session confirmation, assert the stamp in the next person token, refuse an assertion without user verification, race last-factor removals, interrupt app replacement across restart, and reject a reused recovery code. Public passkey authentication must be reached through its public route; a confirmation-only test cannot satisfy it.

The flood observation uses Miniflare’s real rate-limit binding locally for “limited”, a controlled core clock for reset, and one private-stack binding-reset check. A controlled substitute preserves wiring coverage only. Real Turnstile is a separate release observation; a local siteverify stand-in supplies no hosted-provider credit. Status: partial, R1-O18, R1-O19; audit R1-X5.

B1-C · Organizations finished: Program Design

The existing sign-in store supplies own-membership facts and a new scoped person read. Better Auth still checks and writes organization selection. The public response boundary narrows the native reads needed by the shipped switcher. BG receives facts and components, while keeping ownership of setup and destinations.

The three things for you

The subject read is bracketed by live session/permission checks. The self-view never asks about another person. The native full-organization response is projected before any HTTP consumer sees it; internal native API calls keep their full shape.

The three owner choices remain open. The fully described recommendation is a separate lookup page, exact email and the shipped switcher. Choosing a roster or embedding the lookup reopens the named affected design before code starts; there is no runtime variant flag.

The owner's account answer says “your organizations (choose one)” (Fleet transcript:86867). R13/R14 put the people authority in sign-in. Source was read at Switchboard f3b2b88b, Better Auth 1.7.11 and Better Auth UI 2b028ec5/1.7.34. This is a design, not a build or feasibility run.

The closed state union is none | chosen { organizationId } | cleared { by: 'foreign-choice' | 'full-read' }. The closed events are row-observed { selection: OrganizationId | null }, native-refusal-observed { by, selection: OrganizationId | null } and read-unavailable. Initial state is none; the observation carries a fresh native session readback, not a cached mutation response. Context has no dependencies.

M2 · Invitation as lookup reads it

The state union is unread { invitationId } | pending { invitationId, expiresAt } | expired { invitationId, expiresAt } | accepted { invitationId } | cancelled { invitationId } | rejected { invitationId }. Unread is internal initialization, not a public answer. Events are row-observed { snapshot } and clock-moved; context is { now } from the injected clock. A snapshot includes the parsed native status, ID and expiry.

After every applied step: one invitation identity; pending iff a last-observed raw pending row has expiry strictly greater than that step's injected now; exactly-at-now is expired. Refused steps retain the prior state and its last-applied context. Clock movement cannot change an observed nonpending status. Moving the injected clock backwards can change expired back to pending: expiry is a derived read view of the same pending row, not a terminal stored event. Only a new row observation changes a native status. All snapshots decode before transition; invalid status/expiry is unavailable, never an invented event or not-member.

Native write discipline, modeled as observed: accept reads pending and unexpired, then claims pending → accepted conditionally via fromStatus; a lost claim refuses. Its member-work failure rolls back accepted → pending conditionally. Cancel checks native permission but updates status by ID without a pending condition; it can overwrite accepted while a membership remains. Reject checks pending before an ID-only write and remains publicly closed here. A later snapshot can therefore move accepted to cancelled or pending; do not assert terminal immutability. Native accept rejects expiry before its own clock (<), whereas this lookup requires expiry after injected now (>); equality differs. Do not patch the native writer to make these policies identical. BG still owns guarded Decline. No project invitation write or effects runner is introduced.

Transition-result refused means no assignment, distinct from the next state named refused that displays a completed business denial. Those meanings must have separate types.

Conditional local write: the island owns one synchronous current-state reference. Its apply(event) reads that reference, calls the pure transition, assigns only a next result, then renders a snapshot. React render state is a derived view, not a second decision authority. Commit pending before launching fetch, and capture that resulting generation; callbacks apply events against the current reference. No fetch runs inside a React updater or the pure transition. Unmount commits disposed without rendering. Editing returns idle, permitting a new submit while an old response is held. This local phase/generation guard is the conditional write; it adds no SQL, persisted version or global store.

Reading a person's own organizations

readPersonOrganizationContext takes one props object: actor (null or parsed person/session IDs) and store narrowed to persons.readPersonSession and organizations.membershipsForPerson. Its result is PersonOrganizationContext. The existing session read already enforces verified email and expiry using the injected clock (person-session-store.ts:88–119).

  1. Null actor or a missing/expired session returns signed-out. Store/decoder failure returns unavailable.
  2. Read only that stored person's memberships. Parse each row through the existing schema and map it through organizationChoiceSchema.
  3. Apply M1's row-observed event to the parsed stored selection, then keep its chosen ID only if it matches a fresh membership; otherwise return null. This ordinary read has no clearing-origin hint and never invents one. Zero choices remains available. Never write the session or use the presence of a selection to grant a role.

The new GET /api/auth/organization/self-context endpoint accepts no person ID or query keys. It gets native session context with getSessionFromCtx(context, { disableCookieCache: true, disableRefresh: true }), following second-factor-authorization.ts:23–36, then passes parsed IDs to the reader. Status is 200 for available, 401 for signed-out, 503 for unavailable, with the corresponding strict body and cache-control: no-store.

On /owner-ready, replace the handler's manual membership-selection block (sign-in-http-handler.ts:217–248) with this same reader, using the native session already read there. A missing session redirects to sign-in; unavailable shows no memberships and returns the existing 503 path. Keep organization creation eligibility and Fleet setup status derived from the resulting current memberships, and keep factor-enrollment protection.

  2. If a member exists, return member facts and role without reading invitations. Otherwise read all invitations for that exact organization/email, ordered by ID, selecting ID, status and expiry. If any required store is unavailable, emit store-unavailable and return 503/unavailable; if authentication ends, emit permission-refused and return 401/refused; if selection/permission fails, the same event returns 403/refused. Recommended component option: project the public native reads

The two result arrows are different call boundaries. Projection is not a global native hook; only the public HTTP path parses and narrows the result.

The shipped switcher is compatible with a narrow reply. At upstream 2b028ec5, active-organization-query.ts:12–21 explicitly gives the cache a list-organization shape; its fetch uses getFullOrganization (112–116). The switcher:126–154, 201–210 passes hideRole, which disables OrganizationView's member-list query:59–65. Those consumers need no member or invitation fields.

Add projectPublicOrganizationReadResponse({ request, response }): Promise<Response> in the response-release directory, called in handleSignInRequest immediately after providerHandler and before releaseSignInResponse. Its lookup 400-body normalization is required in either component branch. With the shipped component, its native summary projection applies to successful GETs of /api/auth/organization/list and /api/auth/organization/get-full-organization; other native errors/routes are unchanged. Parsing success is mandatory: list is an array of whitelisted summaries; full is one summary or null. Invalid JSON, missing required fields or invalid UUID/date yields fresh 503/unavailable, never the original success body.

Before dispatching either selected native read, reject every query key with generic 400/invalid-request, before any native subject read or selection effect. The shipped switcher sends no explicit organization/slug/member-limit query when its organization plugin has no slug, as configured here. Its full read therefore addresses only the current session choice, never a caller-selected foreign organization. This prevents native not-found-versus-not-member errors from becoming an organization-existence oracle. The projection module owns this small public-request validator as well as the response projection. Internal API queries are unaffected.

For those two native paths, the existing provider before-hook also calls the same endpoint-context/self-context authentication helper: disable cookie cache/refresh, require verified current stored session, map signed-out to 401 and unavailable to 503. It adds no owner permission to a self read. The plugin's own self-context endpoint and the page handler reuse that helper/reader rather than maintaining a second authentication rule.

Construct the projected JSON response with the native success status and copied headers, replacing the body/content type, deleting old content-length and setting cache-control: no-store. This retains native cookie headers. Apply no-store to all selected public organization-read replies, including errors; preserve native error status/body apart from the lookup's documented 400 normalization. Whitelist only summary fields; do not spread the object then subtract known secrets. Full/list replies omit members, invitations, counts, metadata, Fleet stamp fields and future extras for all public callers, including owners. Internal provider.api calls bypass this HTTP fence and remain native.

Keep native membership checks and the following native effects, checked in installed better-auth@1.7.11/dist/plugins/organization/routes/crud-org.mjs: list reads only the signed-in user's organizations (436–452); full checks membership and can clear selection before a refusal (353–372); set-active can also clear before 403 (419–433). Projection changes only successful public reply contents. It adds no permission cache, preservation wrapper, new native endpoint or library patch.

Library behaviour the design keeps

  • A foreign choice clears the current one. Better Auth 1.7.11 dist/plugins/organization/routes/crud-org.mjs:419–433 writes activeOrganizationId: null before throwing 403 when the caller isn't a member. The existing foreign-choice test checks the 403 and that no membership was created; it does not check that the earlier choice survived. We keep the native behaviour and read the session back after any refusal.
  • The member list is too open. crud-members.mjs:437–481 admits any current member and returns every member and a total. It does not check organization:view. It stays closed; the lookup is our own owner-checked read.
  • The session helper hides database failures. dist/api/routes/session.mjs:247–265: getSessionFromCtx catches every error from the native getSession and returns null, so a database failure looks like “signed out”. The native getSession endpoint itself returns null for no session (:164) and throws INTERNAL_SERVER_ERROR on an adapter failure (:229–232). The new reads call the native endpoint directly so the two stay distinct.
  • The broad before-hook acquires first. provider-configuration.ts:230–238 calls getSessionFromCtx for every /organization/ path with cookie cache off but refresh on, and the result is then cached on the context. The new read paths are excluded from that hook so their own acquisition is the first one.

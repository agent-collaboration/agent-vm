Sign-in navigation: design

Switchboard's signed-in pages get one shell: a stock shadcn Sidebar, which opens as a Sheet from ☰ on phones, plus an organization switcher. Destinations are shown, and enforced on the server, by permission.

Phase 1 (this deliverable) ships only what is safe on today's server contracts:

  • the shell itself;
  • Me: passkeys, authenticator and recovery codes, recomposed in shadcn, with the layout-shift fix;
  • Sign out of the current session, through a sign-in-owned route;
  • People, moved into the shell.

Everything else is listed as a later phase, with the owner or contract it waits on (see Later phases).

Why it narrowed: the review found that Better Auth's native session list, revoke, invitation reject and organization delete aren't safe to open as shipped. Each needs its own server contract first. Review report.

N2One server-side route rule (see Permissions) decides which destinations appear, which pages render, and which reads and actions are admitted. If the switch is refused or unanswered, it stays on the current page and organization and shows the error. A lost reply after a committed switch is handled by that readback.
N4Me: passkeys, authenticator and recovery codes, the current content, recomposed. Card/CardHeader with Add passkey in CardAction. The list goes in a reserved CardContent slot with a Skeleton while loading. Rows use Item, which replaces the hand-styled <li> at auth-ui/.../passkey-manager.tsx:72. The existing hooks, audited deletion and guarded factor operations are unchanged.
N5Sign out of the current session. A sign-in-owned route (POST /api/auth/switchboard/sign-out, a working name) deletes the current session through the existing fenced session-deletion path (authorization-fenced-adapter.ts:71–79,95–105). It reads back that the session is gone, and only then clears the cookie and redirects to /sign-in. If deletion or readback fails, it keeps the cookie and shows "Couldn't sign you out; try again". Native /sign-out stays closed, because it clears the cookie even when deletion throws (Better Auth api/routes/sign-out.mjs:41–54).
N6People moves into the shell at /people, as the existing product island. Its reads (GET /api/auth/organization/people-list, GET /api/auth/organization/people, POST /api/auth/organization/person-membership) and their server checks are unchanged.
N7Entry without breaking setup or the CLI: the shell is entered only once the person is ready (BG's page decision: factor set up, organization chosen, no pending CLI continuation). /owner-ready keeps its current job unchanged: resuming authorization, factor and organization steps, the Fleet CLI continuation and its deadline (sign-in-http-handler.ts:231–316). Its "ready" state shows a link into the shell, not a redirect.
N8Loading a list never moves the Add passkey button, or the next persistent control on the page.
N9Components: shadcn primitives already in the shared tool-access-ui package (Sidebar, Sheet, Card, Table, Alert, Button, Skeleton, Separator, Badge, AlertDialog), plus two official Base Mira registry additions, dropdown-menu and item. Nothing is hand-built; each element maps to the inventory.
N10The existing admin page stays: /organization-admin (create workspace, workspace lookup and change records, with factor confirmation) is not retired in phase 1. The switcher links to it as "Organization admin", for owners only, until a later phase replaces each of its functions.

The route rule (one table, enforced on the server)

Destination or actionPermission in the active organizationWhere it's enforced
Me (/me), Sign outAny live, verified sessionThe page handler; the sign-out route
People (/people) and its readsorganization:viewThe existing People path (live session, selected organization, organization:view), already server-checked
Organization admin link (/organization-admin)Owner (existing checks on that page)That page's existing signed forwarder, which binds the operation to the caller's organization

The Sidebar is built from this same table, using the server-confirmed organization, so a hidden link can never be the only guard. Back after a switch re-renders from the server, so a stale page can't act in the old organization.

Sign-in navigation: design

Switchboard's signed-in pages become one shell.

  • A shadcn Sidebar with four destinations: Me / People / Machines / Workspaces. On phones it opens as a Sheet from ☰.
  • An organization switcher in the header.
  • One page per job, in place of today's crowded "Your account" page and the unstyled admin page.

Everything is stock shadcn and Better Auth UI, as shipped. The only exceptions are listed in the shadcn inventory, each with its documented composition.

The product gaps this closes:

  • there is no public sign-out;
  • there is no navigation;
  • the "Add passkey" button moves when the list loads.

The shell

  • Routes: /me, /people, /machines, /workspaces and /workspaces/:id. Each is a real route, so browser history and links work. The Sidebar uses SidebarMenuButton rendered as a link, with isActive and aria-current="page".
  • The landing: /owner-ready (today's account page, sign-in-http-handler.ts:162,231–313) redirects to the first permitted destination. The setup flow (/setup, BG) is unchanged.
  • The switcher: a DropdownMenu with a DropdownMenuRadioGroup of memberships (role shown), then Settings, Audit and Delete organization for owners. Delete is variant="destructive" and confirmed in an AlertDialog. Switching uses the existing chooser readback (person-organization-choice.tsx:14–55), then lands per N3.
  • The CLI banner: a shadcn Alert under the header with Button Continue and Cancel, and no close ✕. Cancel tells the CLI the sign-in was refused.

New public routes on sign-in

Today the public allowlist (response-release/sign-in-request-handler.ts:11–98) admits none of these. Each is a Better Auth route already, added to the allowlist with its tests:

  • list-sessions, sign-out and revoke-session. "This session" is marked from a safe session ID, never the token, because session reads strip the token (session-read-without-token.ts:1–22).
  • organization/list-user-invitations and organization/reject-invitation. BG's guarded Decline rule applies: it updates only while the invitation is pending.
  • organization/update and organization/delete, owner only. Delete needs a fresh second factor.

Dependencies outside sign-in

  • Machines List and Revoke: central's S5 private admin routes. Revoke exists; List is new.
  • Workspaces: central's workspace list, plus Allow and Withdraw (S5 #7, second). Until central mounts them, Workspaces shows an empty state saying it's coming soon, and People, Me and Machines ship first.
  • The Router's refusal text: the Mac Lead.

Build order

  1. The shell and Me: Sidebar and Sheet, the switcher, the CLI banner, Me with sign-out, sessions and invitations, the layout-shift fix, and the new public routes.
  2. People moved into the shell, and the unstyled /organization-admin page retired.
  3. Machines: List, Revoke, and Waiting for approval. This waits on central's List.
  4. Workspaces: waits on central's workspace list and Allow/Withdraw.

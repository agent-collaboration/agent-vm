The owner's production steps

The local feature acceptance supplies a tested capability. It does not supply the owner's production authority, controls or execution receipt.

These are explicitly the owner's actions after local qualification, review and release/deployment approval. Local proof does not authorize them or make them complete.

  1. Permission-policy rollout, before enabling new-map issuance: verify the actual source/native artifact and provide the trusted target pause which remains held across runner failure/restart. Invoke private stop: active N/old → stopped N+1/old. Wait for Central's ACK, deploy/load compatible native map, then invoke private resume: active N+2/new. Hold target issuance through that ACK and release only on verified completion. Unknown replies retry the exact payload; no same-version rewrite, optimistic ACK, global ACK gate or stamp re-sign. Preserve production source/floor/pause receipts. This policy operation is distinct from the optional signing-key window below.
  2. Choose the retirement mode and accept its cost. Confirm the released source/artifacts and deployment match the locally qualified capability. Provision the private maintenance binding/tool access only to the owner's maintenance tooling; the gateway and public HTTP remain without it.
  3. Inventory every production key-dependent credential family, maximum outstanding expiry and explicit client key pins. Establish the actual admission pause/drain and preserving-state restart controls for that deployment. Unknown consumers/controls block withdrawal.
  4. If A, reserve the measured maintenance window, pause sign-in/affected administration, drain old requests and run private prepare/re-sign/confirmation. Keep the old published key until all organizations and credential-safety checks pass.
  5. Invoke withdrawal, perform preserving-state cold rechecks of every organization, and reopen only after verified success. A pre-withdrawal failure keeps the old key; a post-withdrawal failure stays in maintenance for owner recovery. No automatic successful rollback is promised.
  6. Retain the nonsecret production report and actual target identities. This is production evidence distinct from the local acceptance. Any backup or later selected old-data import follows the owner's separate 13 Nov decision.

If key option B is chosen, replace the key-window preparation/withdrawal procedure only after its live-epoch design, schema/contracts and no-pause proof are approved and delivered.

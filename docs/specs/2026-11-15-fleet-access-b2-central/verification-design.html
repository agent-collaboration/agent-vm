B2 · Central organizations: Verification Design

Prove the completed page against both real local sign-in/Central pairings and the actual native keys. Reuse the existing component/refusal/recovery cases, then add the observations they cannot supply. Every row below is planned, not a passing receipt.

The three things for you

A later workspace survives more than 100 records; all producer record variants parse; a malformed row names its ID/column without a partial-success page; the real browser confirms or cancels; and cold restart with the old published key absent still serves the same organizations and directory.

V5 runs the selected retry branch; V10's maintenance rehearsal applies if a window is chosen. A live fence needs its design/proof first. V14 distinguishes engine compatibility now from a whole console here; the latter needs the complete added surface design/proof. All three choices remain open. Production key and policy operations remain owner steps.

The references are S1–S16, the approved B2 proof rows and the later owner answers quoted in Requirements. The 15 Nov machine correction requires Hegel on the real pure transitions/effect data, not just scenario coverage. Historical WS14 results at 116e499e/ea030e513 are evidence of that older target only.

The one target each observation names

Key: blue is pure logic, teal component evidence, amber real local interactions, green the retained evidence. Hosted provider/Turnstile, deployed bindings and production execution remain separate.

  • Consumer: final Switchboard PR commit after B1-A merges, clean isolated worktree and built modules from that same source. Record Node/pnpm, Better Auth 1.7.11, Drizzle, browser and bridge versions.
  • Producer: checked current Central commit including Lead A: central workspace directory read after its engine merge. Current baseline is e7b709f6; the final dependency commit replaces it. Rebuild exact native/workerd artifacts and mirror fixtures; update the existing pin inventory with hashes. Do not relabel the old ea030e513 artifacts.
  • Pairings: Node sign-in/better-sqlite3 → private socket → real Tokio Central; workerd sign-in/D1 → private service binding/link → real workerd Central. Both are required, with heavy runs on Sunclaw.
  • Time: one controlled clock per harness, including Better Auth's native Date through its existing harness support. Expiry/cutoff/credential windows advance explicitly. Waits are process/protocol/DOM events; no sleeps or real-clock reads.
  • Custody: source/build/configuration/client tuple, offered/selected case inventory, artifact hashes, readiness, invocation receipts, direct exit/counts and per-step records. Sensitive runtime state remains private. The public report has no tokens, statement bytes, codes or private keys.

V2 · Authority, isolation and disclosure (S2)

Proven by: two real provisioned organizations with distinct directory/history sentinels. Owner A may administer A; member A and owner B cannot read A's directory, history or sanitized status, create there, or obtain a replacement operation ID from a refused cross-organization request. Route a request naming A to B's store and require the same no-disclosure/no-effect result as a nonexistent subject.

Retain actual current-session, permission, proof, audience, request-time and revision-fence cases in organization-admin, fleet-admin-relay and authorization-fence. Private maintenance routes have no public HTTP path; the ordinary gateway management binding has no maintenance methods. Revoke/remove while a fresh authorized-state read is held before dispatch, then release it and require no protected DTO. Expire a session during the read and require no released page.

Wrong builds: bypass the status permission check; select the directory without organization admission; omit the shared Fleet guard. Each corresponding sentinel/effect assertion fails. Limit: machine/session isolation outside these admin operations remains B3/B4's proof.

V6 · Complete directory/history, including corruption (S6)

Proven by: create at least 101 workspaces and more than 100 earlier history records, including a workspace established by Central's supported directory path without a B2 creation record. Traverse each independent cursor through the actual forwarded API and browser. Compare the ID set exactly with Central's authoritative directory and record set; no duplicates/omissions. Empty, one-row, exactly-limit, limit+1, final-empty history, invalid cursor/limit, concurrent insert then Refresh and a failed later page all have explicit expected states.

Permanent client unit cases reject nonprogress/out-of-order/duplicate/excess rows and inconsistent next cursors. A Hegel family in test-support compares the pure pagination accumulator against a separately written sorted-set model on stable generated collections, with deterministic settings and no stored example database. It preserves the real parser/accumulator; it does not replace the joint directory proof.

Use Lead A's accepted test-support stored-column mutation role to corrupt each projected workspace field in the organization object's owned directory, then call the real route. The whole page fails 503 with {error:'corrupt', row:{workspaceId}|{rawKey}, column}: no partial-success array, skip or coercion. Test both a valid lowercase UUIDv7 and an invalid stored key, bounded to 128 Unicode code points with column workspace_id. Unknown error/column, both row keys, oversized raw key, a valid UUID relabelled rawKey or rawKey with another column are malformed replies. Include multi-code-unit characters at the exact boundary using the producer's fixtures. The client retains a typed corrupt-row result and displays its diagnosis; it sends no empty-Central recovery/provision request. Other bare 503s remain unavailable. Only an authorized admin gets the diagnosis; V2 covers refusal before the read. Final mutation-control name and production absence proof belong to the named Central slice.

Wrong builds: restore first-100/history-based enumeration; drop a later page; skip a corrupt row; flatten corrupt diagnosis to an empty success. Each exact set/error assertion fails. Limit: pages are live reads, not a multi-page snapshot. No new snapshot/retention mechanism is implied.

V10 · Actual keys, quiescence and preserving-state cold restart (S11–S12)

The Verifier's last read is outside the maintenance runner's report. A report that says complete while the old key or warm cache still decides the result cannot satisfy this observation.

Proven by, if A is selected: a full local maintenance rehearsal on both real pairings, using the production maintenance capability, native Better Auth key creation/storage/signatures, actual public JWKS and actual Central storage. The harness controls traffic outside the capability; a reported “quiesced” boolean is insufficient.

  1. Provision at least two organizations under a real old native key. Include an idle/not-due organization and an unanswered renewal. Separately lose a committed setup reply, leaving a real old-key Central stamp with sign-in settingUp: the all-organization inventory blocks retirement until the existing explicit setup retry confirms it, with no automatic provisioning send from the maintenance path. Retain nonsecret old key ID, stamp digests and directory IDs. Keep private key bytes out of reports.
  2. Hold a real request after it selected the old key, and separately hold deferred after-response signing work. Begin the maintenance traffic pause, prove new public admission is blocked, and prove drain is not complete until both held works settle. Release their event barriers; then prepare the new key through native createJwk. Verify new current selection and both published keys. A same-time selection mismatch returns unfinished.
  3. Re-sign through the existing conditional rules, settle pending bytes, independently read every real Central stamp and compare to the native current key. Fault one organization's replacement/read: retirement is blocked and the actual old JWKS key remains. A lost key-creation result remains unknown; resuming uses observed metadata, with no second automatic key creation.
  4. Inventory the actual local credential families, record the last possible old-key issue, and advance the controlled clock to the safe expiry. One millisecond before it, withdrawal is refused. No test waits on wall time. A drifted current key/new organization before withdrawal invalidates the previous readiness result.
  5. Withdraw the explicit old key through the real native expiry policy. Read actual JWKS: old absent, new present. Verify a new real signature. Keep the live sign-in host stopped from accepting ordinary work during final checks.
  6. Terminate and await exit of each captured Central process/runtime. Restart over the same private persistence root, with an empty runtime verifier cache. Read stored stamp and authorized directory through the real link: same organization/workspace IDs, replacement key/digest, no re-provisioning or new workspace effects. The Verifier independently performs another preserving-state restart/read; it does not trust only the operation's success report.
  7. Inject a cold-probe failure after withdrawal. Require withdrawn-unverified and maintenance remaining closed; no success/reopen or automatic key restoration. A public request and the ordinary gateway binding still cannot invoke maintenance. A successful full run may reopen only after every independent check passes.

Wrong builds: skip idle or setting-up organizations; treat an unfinished array as complete; claim drain while the old request/deferred signer is held; retire before credential safety; trust a prior report after target drift; keep a warm verifier instead of restarting; restart into empty storage; return success after a failed cold read. Each has a named independent row/key/process/read assertion. Preserve both intended-red and restored-green receipts.

If B is selected: V10 stays blocked on the approved live-epoch design. It must instead force the paused old signer across an epoch advance, prove its release/write is fenced on both hosts and all affected credential paths, and retain no-pause availability evidence. The maintenance rehearsal is not proof of that alternative.

Limits: production traffic controls, actual production credential inventory, hosted execution and a production key change are owner steps. The local duration supports later window sizing only. If the preserving-state fixture needs a Central hook, name it and obtain Lead A's slice; do not use empty restart.

  • Force a second factor refusal after successful confirmation: settle visibly after one retry.
  • Traverse directory/history beyond 100 records, including current producer variants and a later-page failure/retry. Refresh status and observe the distinct valid/pending/refused/expired conditions.
  • Use a member/other-organization browser; show no protected metadata/effects. Inspect responses/state for credentials and inspect actual script/CSP errors.
  • At 400 px and desktop, controls, field errors, confirmation, status and Load more remain visible/usable in the existing design system. Capture only nonsecret screens.

Wrong builds: serve the old page/controller; omit the new island/CSP nonce; resume an action after cancellation; strip paging state; show success on an unavailable lookup. Required step/network/state assertions fail. Limits: the virtual browser/provider setup is local; physical passkeys, live Turnstile, staging and production are not observed here. No equivalent manual repetition is required after the real-browser scenario passes on the frozen target.

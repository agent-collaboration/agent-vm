B2 · Central organizations: Verification Design

Prove the completed page against both real local sign-in/Central pairings and the actual native keys. Reuse the existing component/refusal/recovery cases, then add the observations they cannot supply. Every row below is planned, not a passing receipt.

The three things for you

A later workspace survives more than 100 records; all producer record variants parse; a malformed row names its ID/column without a partial-success page; the real browser confirms or cancels; and cold restart with the old published key absent still serves the same organizations and directory.

V5 runs the selected retry branch; V10's maintenance rehearsal applies if a window is chosen. A live fence needs its design/proof first. V14 distinguishes engine compatibility now from a whole console here; the latter needs the complete added surface design/proof. All three choices remain open. Production key and policy operations remain owner steps.

The references are S1–S16, the approved B2 proof rows and the later owner answers quoted in Requirements. The 15 Nov machine correction requires Hegel on the real pure transitions/effect data, not just scenario coverage. Historical WS14 results at 116e499e/ea030e513 are evidence of that older target only.

The one target each observation names

Key: blue is pure logic, teal component evidence, amber real local interactions, green the retained evidence. Hosted provider/Turnstile, deployed bindings and production execution remain separate.

  • Consumer: final Switchboard PR commit after B1-A merges, clean isolated worktree and built modules from that same source. Record Node/pnpm, Better Auth 1.7.11, Drizzle, browser and bridge versions.
  • Producer: checked current Central commit including Lead A: central workspace directory read after its engine merge. Current baseline is e7b709f6; the final dependency commit replaces it. Rebuild exact native/workerd artifacts and mirror fixtures; update the existing pin inventory with hashes. Do not relabel the old ea030e513 artifacts.
  • Pairings: Node sign-in/better-sqlite3 → private socket → real Tokio Central; workerd sign-in/D1 → private service binding/link → real workerd Central. Both are required, with heavy runs on Sunclaw.
  • Time: one controlled clock per harness, including Better Auth's native Date through its existing harness support. Expiry/cutoff/credential windows advance explicitly. Waits are process/protocol/DOM events; no sleeps or real-clock reads.
  • Custody: source/build/configuration/client tuple, offered/selected case inventory, artifact hashes, readiness, invocation receipts, direct exit/counts and per-step records. Sensitive runtime state remains private. The public report has no tokens, statement bytes, codes or private keys.

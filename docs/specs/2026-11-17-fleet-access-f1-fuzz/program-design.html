F1 · Fuzz testing for sign-in: Program Design

How it's built, revision 2, after design review F1–F10. F1 is test code only: no product file changes and no CI gate changes. Pure tests go in the unit lane. Anything that needs a live Miniflare or Node host (the provider inventory, dual-engine storage, host requests) goes in the existing host e2e lane, which CI already requires (ci.yml:43), per Switchboard's AGENTS.md:35. Bombadil runs through an on-demand driver in scripts/.

Coverage (S1)

  • handler-routes.ts lists the routes the outer handlers own, written by reading sign-in-request-handler.ts and sign-in-http-handler.ts.
  • route-classification.ts is the independent table (E2). Each row: method, path, exposure, request parts, documented answers, disclosure rule, permitted refusal effects. It's written from the specs and tests, not computed from the product allowlist.
  • route-coverage.host.e2e.test.ts builds the live provider inventory, then checks that provider rows plus handler routes equal the classification rows, and that the reachable rows equal the families.
  • The pure unit test checks the table's own consistency: every reachable row has request parts and answers.

Requests (S2)

  • Families: one module per reachable row, exporting { route, callers, generate }. generate draws:
    • the query map for GET routes;
    • the URL-encoded form for the token route;
    • the JSON body for body routes;
    • malformed JSON and the wrong content type where Fetch allows them (no GET body: Fetch rejects it before the host).
    Values come from Hegel generators per field: valid, near-valid, boundary.
  • route-requests.host.e2e.test.ts: per family, caller and SIGN_IN_TEST_HOST, it runs hegel.testAsync (200 cases default, derandomized in CI).
    • Each case: it sets up fresh fixture state for its caller, sends through the harness, then checks the S2 answer, disclosure and effect rules from the row.
    • Disclosure: it scans body and headers for every credential class (reusing credential-free-refusal.ts) and for identities beyond the caller's entitlement.
    • Effects: a stored-row snapshot diff before and after, allowing exactly the row's permitted effects.

Organization sequences (S3)

  • organization-model.ts (pure, unit-tested): people, organizations, memberships with roles, invitations, sessions, and fence pairs keyed on (organization, person) with an active flag. It's written from the domain rules and the fence contract (authorization-fence-mutations.ts:233–354, person-session-store.ts:239).
  • organization-sequences.host.e2e.test.ts: a hegel.stateful.StateMachine with runAsync, on each storage engine via the existing dual-storage host.
    • Each rule performs its operation through the real entry: the Better Auth organization routes or service operations through the harness, as the right caller. It applies the same operation to the model, then reads stored state back through the existing store readers.
    • Refused operations must be refused by both.
    • Invariants are S3's rules plus “model equals stored projection”, all with alwaysCheck: true.
    • Pools hold people, organizations and sessions. 50 steps per case; 100 cases per engine.

Bombadil (S4, S5)

  • Dependency: @antithesishq/bombadil, an exact-pinned dev dependency. The driver maps the existing CHROME_BIN to Bombadil's CHROME variable.
  • Specs: sign-in-signed-out.ts, owner-pages.ts and member-people-denied.ts. Each:
    • keeps noUncaughtExceptions and noUnhandledPromiseRejections;
    • replaces noConsoleErrors with an allowlisted version;
    • replaces noHttpErrorCodes with a navigation-status property that accepts only the route's documented refusal (403 plus generic content for the member campaign);
    • adds the S2 disclosure rule over page text and attributes, per campaign;
    • uses action generators that stay inside the page under test.
  • Passkey click-only witness: the harness counts passkey-challenge requests on its own side. The driver reads the trace's recorded actions (bombadil trace JSON) and counts clicks on the passkey button. Equal counts pass. A request with no click fails, regardless of timing, which avoids the snapshot-timing problem.
  • Driver, run mode, per host:
    • start the harness;
    • seed the campaign's people, organization and sessions;
    • run bombadil browser test --headless --time-limit 5m --exit-on-violation --output-path <private> <issuer>/<page> <spec> with one --cookie per cookie;
    • then compare the challenge counts, record the exit code, trace path and campaign settings, and tear down.
  • Driver, replay mode: recreate the same host, fixtures, controlled clock and signed-in state, then run bombadil browser test --reproduce <trace> against the new issuer, with the same spec and cookies, and without --time-limit or --exit-on-violation.

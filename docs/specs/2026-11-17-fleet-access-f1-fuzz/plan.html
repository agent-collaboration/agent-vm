F1 · Fuzz testing for sign-in: Plan

Status: designed 17 Nov. Next comes an independent Sol xhigh review of these pages; the build starts when it's READY. Implementers and Verifiers read all six pages first; the design wins over these steps.

Split, 17 Nov (my call after design review F14)

  • Build now: the Hegel parts: S1 coverage, S2 requests, S3 organization sequences, and S5 for Hegel. The review closed every finding on them.
  • Unfinished, not waived: S4 Bombadil and S5 for Bombadil. The startup handshake between the driver's observers and Bombadil didn't converge on paper (review F14: on a blank page Bombadil has no valid action, so it errors before the driver can navigate). Before any further design, one bounded feasibility probe on Sunclaw tries two handshakes against a tiny local page with a deliberate on-load request:
    • (a) the driver's browser-level Target.setAutoAttach with waitForDebuggerOnStart arms its observers on the target Bombadil creates (test-external --create-target), then releases it;
    • (b) a hold-and-release start page that Bombadil can act on, kept inside the issuer origin.
    The probe reports which one records an on-load challenge before any click and lets Bombadil explore. The S4 design is then corrected from that result and re-reviewed.

Order and overlap

  • Base: public main. F1 fuzzes the endpoints that exist when it lands. The S1 coverage test makes the PR that lands later add families for any endpoint B1-B or B1-C adds, so whichever lands second extends F1.
  • Files: new test and support files only, so conflicts with B1-B and B1-C are unlikely.

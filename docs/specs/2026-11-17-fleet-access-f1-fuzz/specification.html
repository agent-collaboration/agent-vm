F1 · Fuzz testing for sign-in: Specification

What must be true. Each obligation (S) traces to a need (U) on Requirements. Facts about the tools come from source, recorded in tmp/2026-11-17-fuzz-research/report.md: Hegel 0.4.10 as installed, and Bombadil at 7c7081b (0.7.10).

Obligations

S1 · Every endpoint has a body family (U1)

Every endpoint in installedProviderEndpointInventory that its existing classification marks reachable by a browser or CLI MUST have exactly one body family. A coverage test MUST fail when an inventoried reachable endpoint has no family, or when a family names an endpoint that isn't in the inventory. A new endpoint therefore can't ship unfuzzed.

S2 · Generated bodies get only documented answers (U1)

For each generated request, on each host, the endpoint MUST answer with its documented success, or one of its documented refusals with the generic body. The tests MUST observe all three of these:

  • no 5xx, except the documented 503 for an injected storage fault, which F1 doesn't inject;
  • no response body containing a session token, a cookie value, or a person's email or ID other than the caller's own;
  • no change to stored rows when the answer is a refusal.

Requests go through the real host entry (the existing harness's auth(pathname, init)), as signed out, signed in as a member, and signed in as an owner.

S3 · Storage rules hold over any sequence (U2)

Over Hegel-generated sequences of real store operations, run on each storage engine through the injected Drizzle stores, each rule MUST hold after every step (checked every step, never sampled). The operations are: create organization, invite, accept, cancel, remove member, change role, choose current organization, create and expire session, and delete person. The rules:

  • R-owner: every organization has at least one owner;
  • R-choice: a stored current-organization choice is null or an organization the person belongs to;
  • R-removed: a removed member has no live session scoped to that organization;
  • R-fence: a person's fence revision never decreases, and increases on every member or session delete;
  • R-invite: invitation states move only along the documented lifecycle.

Operations the domain refuses (for example removing the last owner) MUST be refused with no row changed.

S4 · UI properties hold under exploration (U3)

Bombadil campaigns, each on both hosts, cover:

  • the sign-in page signed out;
  • the owner page and People page signed in as an owner;
  • the People URL signed in as a plain member.

Every reachable state MUST satisfy:

  • Bombadil's defaults (no uncaught exceptions, no unhandled rejections, no console errors, no failing navigation status), except console messages on an explicit allowlist, each with its reason;
  • no session token, cookie value or other person's email in page text or attributes;
  • passkey click-only: no passkey-challenge request until the passkey button is clicked;
  • a plain member never sees People rows;
  • every refused route stays refused.

S5 · Findings are reproducible (U4)

Every finding MUST record:

  • for Hegel, the failing case's printed values and seed;
  • for Bombadil, its private trace path and reproduce command.

A fixed finding MUST become a permanent ordinary regression test. Hegel runs derandomized in CI so results repeat.

S6 · Limits are stated (all)

Results hold for the local hosts, software authenticator, controlled providers and injected clock only. Bombadil traces may hold sensitive values; they stay private and never go into git or reports unredacted.

An owner can create an organization and permitted workspaces through the real local services. Organizations stay separate, and their signed statements renew and recover safely in the observed cases. The complete workspace list and renewal status are missing, and safe old-key retirement has not been completed.

Overall verdict: partly delivered. Local proof is not hosted or release acceptance.

Open for the owner: what does a retry promise?

The approved B2 wording promises the first answer again. Current central keeps that answer for one day. Afterward it may return a name refusal, and the page or command line checks whether its workspace already exists. I found the limit in the Central Lead’s account, not a first-hand owner change to the B2 promise.

Recommendation: recover the existing owner-approved central retention contract first. If it does not already settle this, preserve the approved promise until the owner explicitly changes it. This review does not choose a new storage mechanism.

If deferred: late-retry conformance stays unresolved. All development already waits for the owner’s explicit go. No answer here starts implementation.

What needs fixing

  • Show all workspaces and history. Fully fixed means later entries remain reachable after more than a hundred earlier records.
  • Show renewal failures and pending answers. Fully fixed means the authorized owner can see why work is blocked without receiving secret statement bytes.
  • Finish safe signing-key retirement. Fully fixed means every organization survives cold restart under the new key before the old key is removed.
  • Prove the actual administration browser path. Fully fixed means confirmation, cancellation, permission refusal and successful creation are observed with real central on both builds.
  • Align late retries, project/import ownership and retired commands. Fully fixed means the approved contracts have current code and decisive evidence.
